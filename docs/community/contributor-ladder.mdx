This ladder applies to `HarshShinde0/geocr_mcp`. It maps expected work to review rights. Upstream Model Context Protocol has its own ladder. This file does not copy it.

## Roles

| Role | What you do | How you get there |
| :--- | :--- | :--- |
| **Community member** | Open issues, test tools such as `count_eo_scenes` or `create_geocroissant_from_stac`, and comment on proposals | Take part on GitHub at `https://github.com/HarshShinde0/geocr_mcp` |
| **Contributor** | Merge pull requests for bug fixes, docs, or catalog entries | Have one or more merged pull requests in `HarshShinde0/geocr_mcp` |
| **Reviewer** | Review pull requests, check CI, and triage issues | Show steady, high quality work and domain knowledge over several months |
| **Maintainer** | Merge code, publish releases to PyPI, sponsor proposals | Sustained ownership of core areas such as `src/geocr_mcp_server/eo.py`, `src/geocr_mcp_server/spec.py`, or `src/geocr_mcp_server/catalogs.py` |

## How promotion works

Maintainers nominate a contributor for the next step. Nomination considers merged changes, review quality, and conduct in issues and pull requests.

A reviewer needs a track record of clear reviews and accurate issue triage. A maintainer needs broader scope. That includes release work, handling `GEOCR_CATALOGS_CONFIG` and `GEOCR_OUTPUT_DIR` behavior, and review of STAC and GeoCroissant changes.

Nominations are discussed among maintainers. The result is posted on the pull request or issue where the nomination was raised.
