# GenAI-ready data with GeoCroissant: MCP demos

Hands-on material for the GenAI-ready data session at the [Responsible Gen-AI for NASA Earthdata hackweek](https://responsible-genai.hackweek.io/). Every prompt below is meant to be copied and pasted, unchanged, into Claude Code or the Claude terminal.

Specifications used in this session:

- Croissant 1.1: https://mlcommons.github.io/croissant/docs/croissant-spec.html
- Croissant RAI: https://mlcommons.github.io/croissant/docs/croissant-rai-spec.html
- GeoCroissant 1.0: https://mlcommons.org/croissant/geo/1.0

## Learning objectives

By the end of this session, you will be able to:

- Install and verify the GeoCroissant MCP server in Claude Code
- Search for optical and radar scenes with natural language and generate GeoCroissant metadata from the results
- Validate GeoCroissant metadata, inspect its RecordSets, and extract source asset URLs
- Load a GeoCroissant metadata file into a PyTorch Dataset and DataLoader

## Part 1: Setup

### Step 1: Install the GeoCroissant MCP server

From your terminal:

```bash
claude mcp add --transport http geocr https://geocr-mcp-server.onrender.com/mcp
```
### Step 2: Check the tools

Open Claude Code and list the connected servers and their tools:

```claude
/mcp
```

You should see `geocr` in the list. Confirm the server responds:

```claude
ping
```

## Part 4: Responsible Geo-AI examples
Datasets published with RAI attributes, each run as its own science story. The pattern is the same in both: run a query generically, run it again with RAI filters, and watch the answer change. It changes because the metadata carries the responsibility signals, not because the model guessed.


#### Step 1: The generic query

```claude
I'm training a segmentation model for flood mapping. Load the GeoCroissant metadata for the flood area in Brazil. Is this dataset suitable for my task, and which specific assets or bands should I use?
```

#### Step 2: The same query, with RAI filters

```claude
Repeat the assessment, but apply Responsible AI criteria: only recommend the dataset if the rai:dataBiases, rai:dataLimitations, geocr:spatialBias, rai:hasSyntheticData, and prov:wasGeneratedBy fields are all populated. Before making any recommendation, report the values for rai:dataBiases, rai:dataSocialImpact, and geocr:spatialBias, and flag any RecordSet where rai:hasSyntheticData is true.
```

#### Step 3: Explain the difference

```claude
Compare your two answers. Using only the RAI and provenance fields in the metadata (rai:dataBiases, rai:dataLimitations, geocr:spatialBias, rai:hasSyntheticData, prov:wasGeneratedBy), explain what changed between the generic answer and the filtered answer, and what a researcher would have missed without the RAI attributes.
```

What to look for in the output:
- `geocr:spatialBias` confines the dataset to the urban lowlands and Guaíba Lake delta in Porto Alegre, warning that a model trained here will not generalize to upstream steep-slope river basins (such as the Taquari valley) or arid catchments.
- `rai:dataBiases` discloses critical sensor blind spots: optical imagery has severe cloud-cover gaps during flood onset, while radar (SAR) exhibits specular reflection on flat tarmac and airport runways, risking false-positive water classifications.
- `rai:dataLimitations` alerts the researcher that optical and radar rasters have heterogeneous resolutions and different coordinate systems and are not co-registered into an aligned multi-modal tensor, while warning of misclassification in flooded vegetation without elevation priors.
- `rai:dataSocialImpact` highlights disaster-relief benefits while setting an essential safety boundary: unvalidated algorithmic flood masks must not be used as sole guidance for critical evacuation routing.
- `rai:hasSyntheticData` confirms across all RecordSets that the imagery consists of authentic Copernicus satellite observations rather than generative or synthetic samples.
