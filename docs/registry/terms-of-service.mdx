These terms govern use of the GeoCroissant STAC Catalog Registry as shipped in `geocr-mcp-server` and configured in `src/geocr_mcp_server/config/catalogs.yaml:1`. The registry points at public STAC APIs and builds GeoCroissant metadata that references provider assets. The registry does not host raster data.

Verify `get_eo_dataset_details` output and provider documentation before you rely on a dataset for production work.

2. Public STAC APIs. The built-in catalogs are `earth-search` at `https://earth-search.aws.element84.com/v1` and `veda` at `https://openveda.cloud/api/stac`. Both are public HTTPS services. ## For dataset builders

8. Do not abuse providers. The catalog registry queries STAC APIs with `GET /collections` and `GET /search` through `search_eo_datasets`, `count_eo_scenes`, and `search_eo_scenes` in `src/geocr_mcp_server/tools.py:61`. Keep `limit` reasonable for interactive use, and use `count_eo_scenes` before broad scene searches. Respect provider rate limits and caching headers. Downstream consumers should cache catalog lists and collection metadata for the session rather than poll on every call.

9. Attribution. When you publish a derived GeoCroissant dataset, include the catalog URL, collection id, bbox in `[min_lon, min_lat, max_lon, max_lat]`, and `datetime_range` that you used. This matches the `search_summary` returned by `create_geocroissant_from_stac` and makes the dataset reproducible. Cite the upstream collection provider as described in provider docs.

10. License of metadata. Collection metadata returned by STAC APIs and the snapshot in `src/geocr_mcp_server/config/catalogs.yaml:1` is factual and provided for discovery. Your GeoCroissant JSON-LD is your own work product, but it references provider assets that may have separate licenses. The `license` field you pass to `create_geocroissant_from_stac` should reflect the terms that apply to your derived metadata and any redistribution rights you have for the underlying assets.

## For operators

11. Private catalogs. If you set `GEOCR_CATALOGS_CONFIG` to a custom YAML file as in `src/geocr_mcp_server/catalogs.py:21`, you are responsible for keeping that file accurate, for securing internal catalog URLs, and for ensuring that any additional auth you need for those catalogs is handled in your gateway. The validation in `src/geocr_mcp_server/catalogs.py:38` checks shape, not network reachability.

12. Remote server. When you run `geocr-mcp-server` with `GEOCR_TRANSPORT=streamable-http` as in `src/geocr_mcp_server/server.py:122`, the health endpoint at `GET /` and the MCP endpoint at `/mcp` are public on the bind host. Put the process behind a reverse proxy with TLS and apply network controls. The registry itself does not add MCP OAuth.
